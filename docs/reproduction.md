# Reproduction and verification

## Environment

Use Python 3.10 or newer with NumPy, SciPy, PyTorch, Matplotlib, and pytest. The provided `pyproject.toml` specifies broad dependencies, **not** a locked archival environment. For exact paper reproduction, the original package versions, pretrained checkpoints, and data splits would also be needed.

From the TopoFlow root:

```bash
python -m pip install -e '.[test]'
python -m pytest tests -q
```

## Entrypoint and dependency audit

A static inventory of all 62 experiment Python files, including possible import-time work and missing binary inputs, is available at [`entrypoint_inventory.md`](entrypoint_inventory.md). For a curated, task-oriented execution matrix, see [`execution_matrix.md`](execution_matrix.md). Generate a fresh inventory without importing an experiment module:

```bash
python -m tools.audit_entrypoints
python -m tools.audit_entrypoints --format markdown --output docs/entrypoint_inventory.md
```

The second command intentionally rewrites the generated inventory document, not a scientific result. **Do not execute every experiment module to check installation.** Some scripts train, start subprocesses, or overwrite frozen summaries at module scope.

## Safe figure and scoring replay

The selected validation plotting/scoring scripts have explicit CLI inputs, guarded
`main()` entrypoints, and protected outputs. By default, output files are placed
under `reproductions/`, which is excluded from Git; **none of these commands
replace the curated `results/final/` artifacts**. Existing outputs produce an
error unless `--overwrite` is supplied deliberately.

From any working directory, invoke these as Python modules from the repository
root or set the repository on `PYTHONPATH`:

```bash
# Historical, archived direct comparison: read-only score log
python -m experiments.validation.direct_score --output reproductions/direct_score.txt

# Standardized latency score + safety/diversity Pareto figure
# Requires the previous direct-score text (not originally included in v0.4)
python -m experiments.validation.latency_score --direct-score reproductions/direct_score.txt

# Deterministic chart coverage figure (JSON inputs included in repository)
python -m experiments.validation.fig_coverage

# Fidelity distributions (original per-class samples must first be restored)
python -m experiments.validation.fig_fidelity --input-dir results/final/fidelity

# Matched trajectories (original layouts and checkpoints must first be restored)
python -m experiments.validation.fig_trajectories --layouts results/d2/layouts.pkl --v2-checkpoint results/d2/models/V2_s0.pt --p1-checkpoint results/d2/models/P1_s0.pt
```

All commands accept `--help`. The plot/score file arguments include `--input`,
`--output`, `--json-output`, and `--figure-output` as appropriate. Output
locations are *reproduction destinations*, not a replacement for paper figures.

**Regression gates:** `direct_score.py` reproduced the original text exactly;
`latency_score.py` generated byte-identical JSON and Pareto PNG using the
archived paired/latency data plus regenerated direct-score text;
`fig_coverage.py` regenerated the curated PNG byte-identically in the test
environment; `fig_fidelity.py` regenerated a byte-identical PNG on matched
synthetic `.npz` inputs. `fig_trajectories.py` was syntax/import validated only:
its original `.pkl` layouts and `.pt` checkpoints were not available for replay.
These do **not** establish full original neural-experiment reproducibility.

The original figure/scoring entrypoints have been guarded separately from the
bootstrap programs described next. Other legacy training and evaluation programs
still require an isolated working copy before execution.

## Safe bootstrap replay

The Experiment B/C bootstrap scripts have guarded `main()` entrypoints and can
be imported without loading data or writing results. They preserve the original
analysis definitions, random seeds, and bootstrap order. Their default outputs
are `reproductions/baseline_paired.json` and
`reproductions/distribution_fidelity.json`, respectively. They refuse replacing
the corresponding canonical frozen result even if `--overwrite` is supplied.

**Original per-run inputs are not included in the public ZIP.** The commands
below work only after the precise archived files have been restored with their
provenance recorded:

```bash
python -m experiments.validation.baseline_boot --input-dir results/final/baseline --output reproductions/baseline_paired.json
python -m experiments.validation.fidelity_boot --input-dir results/final/fidelity --output reproductions/distribution_fidelity.json
```

Both use 4,000 bootstrap replicates by default; `--bootstrap` allows a smaller
value for a **diagnostic smoke test only**, not for recreating published
confidence intervals. Running without restored NPZ files reports a missing-input
error rather than silently writing an empty report. The baseline script can
report a subset if only some matched per-run pairs are restored: a partial
output must **not** be labeled as the complete published analysis. For
Experiment B, the full archived protocol calls for both datasets, specified
model seeds and three paired sampling-noise seeds per setting.

For the refactor regression, we ran the unchanged legacy scripts against the
same deterministic **synthetic** `.npz` fixtures as the new implementations,
with 30 bootstrap replicates in both runs. The resulting Experiment B and C
JSON files were byte-identical to their legacy counterparts; this is a
calculation-equivalence check, **not** the original study reproduced.

## Safe final-validation entrypoints

The following three refactored scripts import without starting work. They
require missing original `.pkl` and/or `.pt` inputs for actual scientific replay;
their inclusion does **not** mean that Experiment A or B can be fully reproduced
from this ZIP alone.

```bash
# Inspect CLI options without loading a dataset
python -m experiments.validation.chart_soundness --help
python -m experiments.validation.baseline_paired --help
python -m experiments.validation.run_queue --help

# AFTER restoring the exact original inputs:
# Experiment A: default output reproductions/soundness/d2.json + d2_codes.pkl
python -m experiments.validation.chart_soundness --dataset d2

# --limit is explicitly a partial diagnostic, not a paper-replay equivalent
python -m experiments.validation.chart_soundness --dataset d2 --limit 1

# Experiment B: results go to reproductions/baseline/*.npz
python -m experiments.validation.baseline_paired --data results/d2 --runs v2:0:777:20,p1chart:0:777:20

# Queue preview: prints job indices and missing prerequisites, does NOT run
python -m experiments.validation.run_queue
python -m experiments.validation.run_queue --job-index 3

# Explicitly launch ONE selected, potentially expensive job (only after restoring inputs)
python -m experiments.validation.run_queue --execute --job-index 3
```

The queue reuses original solver/NFE configurations and child evaluation
implementation, but redirects both JSONL and intermediate chunks to
`reproductions/direct_queue/`. It **does not** resume from the older archived
`results/d2` or `results/d3` output files. The `--budget-min` flag prevents
starting a *new* subprocess after the budget is reached; it does not interrupt
an already running subprocess. A full queue replay may be costly and is never
started as a smoke test. Select `--all --execute` only deliberately.

The soundness runner retains original RNG seed 2026, chart refinement and
independent geometric checks. The paired inference runner retains route-request
seed 900 and the specified sampling-noise seeds. For fidelity to archived code,
reported inference wall times remain subject to runtime variability. Both
refactored scripts reject destinations inside `results/`; queue execution also
refuses to write anywhere under the archived `results/` tree. Existing paired
NPZs are skipped by default; `--overwrite` applies only to reproduction outputs.

**Verification performed during the refactor:** an original-versus-refactored
comparison on a small, constructed environment gave identical soundness JSON
fields (excluding elapsed seconds) and identical per-code pickle bytes.
On a separate synthetic layout and independently initialized model checkpoints,
the original and refactored Experiment B entrypoints produced identical arrays
for both v2 and P1 + chart-correction at NFE 1, excluding the elapsed-time field.
These comparisons test *calculation parity on synthetic fixtures*, not full
regeneration of any reported paper result. The historical direct-evaluation
child script is unchanged; the queue itself was tested with mocked subprocesses.

## Saved evidence versus raw reproduction

The directory `results/final/` contains saved structured reports for Experiments A–C. The archived reports summarize actual prior runs; they are **not** a substitute for the unbundled source checkpoint and sample archives. Read `docs/evidence_index.md` for an explicit mapping from research claims to files and checks.

Some saved JSON metadata and older script commentary contain paths under the original pre-refactor `outputs/` tree. These are historical source-path fields, not current executable locations; do not blindly rewrite frozen JSON or change its checksums. The public scripts have been reorganized under `experiments/` and curated outputs under `results/`.

## Known migration debt

- Several entrypoints assume they are invoked from the repository root, and many use inline relative data paths. Importing them as generic library modules is not automatically safe.
- Some historical experiment modules execute training and file I/O at import time. Do not recursively import every module as a smoke test.
- Experiment C figure and bootstrap scripts now import common metric definitions from `experiments/validation/fidelity_metrics.py`, rather than executing fragments of another script. Synthetic-data regression checks confirmed byte-identical figure and JSON outputs before and after this change in the tested environment. The real per-sample `.npz` inputs are still absent, so the frozen Experiment C outputs have **not** been independently regenerated.
- The chart construction can be refined beyond 60 grid coordinates, but the evaluated v2 generative model is fixed at 60. Stress-test chart coverage is not a demonstration of trained-model generation in those stress-test layouts.
- The original independent geometry and conditional homotopy properties have different assumptions; numerical crossing-word agreement in invalid-cut layouts is not a general topology guarantee.

## Preserving evidence during code cleanup

Do not edit the saved reports or figure files to normalize wording or filenames. Use repository-facing documentation for renamed paths and keep scientific data immutable. If a figure is intentionally regenerated, review differences and then update its checksum manifest in a separate, documented change.

The existing `results/final/ARTIFACT_SHA256.txt` is a *publication-candidate file integrity manifest*, not an original research-time preregistration or evidence of independent experimental replication.
