## Entry-point hazards and path migration debt

Most historical experiment scripts were designed as **directly executed research programs**, not import-safe modules. Their top-level code can read files, create directories, train models, or overwrite results. Do not run a blanket import test (`import experiments.*`) or recursively execute `.py` files. In the static AST inventory, 58 of 62 scripts contain at least one expression or control-flow construct that *may* do work at import time; this heuristic includes benign calls such as Matplotlib backend configuration and should not be read as evidence that all 59 perform dangerous I/O.

In particular:

- `fig_coverage.py`, `fig_fidelity.py`, `fig_trajectories.py`, `direct_score.py`, `latency_score.py`, `baseline_boot.py`, and `fidelity_boot.py` now use `main()` and explicit input/output paths. Default generated outputs are written to the untracked `reproductions/` tree and cannot silently overwrite existing files.
- `latency_score.py` expects a text report which can now be generated from bundled JSONL via `python -m experiments.validation.direct_score --output reproductions/direct_score.txt`.
- `fig_fidelity.py` still requires the unbundled original sample `.npz` inputs; safe default behavior does not make the missing scientific inputs available.
- `fig_trajectories.py` still requires original layout `.pkl` and model `.pt` archives. No original model replay or image identity is claimed for this script.
- `chart_soundness.py` and `baseline_paired.py` are now import-safe and write outside `results/`; restored layout pickles and model checkpoints are required for full replay. **Remaining hazards:** other historical evaluation/training entrypoints still have import-time work or legacy output paths; audit before running.
- `run_queue.py` is a safe read-only **preview by default**. Launching expensive subprocesses requires `--execute` and an explicit job selection. Output and chunk paths are redirected to `reproductions/direct_queue/`.
- Many remaining scripts assume the repository root as their **current working directory**; reorganization under `experiments/` does not automatically remove these assumptions.

The `results/final/ARTIFACT_SHA256.txt` manifest covers archived scientific evidence. It should not be rewritten simply because documentation or script locations have changed. Preserve original results before any reproduction effort; write regenerated outputs to a separate experiment directory and compare them explicitly.

## Suggested next pass

The next functional refactor should convert a **small, chosen group of research scripts** into import-safe `main()` entrypoints with explicit input and output arguments, beginning with figure/scoring scripts that only consume archived data. Validate byte-level or numerical equivalence before modifying model-training or frozen-validation code. Only after original inputs can be restored or independently regenerated with documented provenance should the repository claim end-to-end paper reproducibility.
